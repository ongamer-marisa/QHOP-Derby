## 模型与配置

附带的 `Horse.blend` 有 51 根骨骼、40 根变形骨骼、964 个三角面和四个材质槽。四条腿有三骨 IK 链，`IK-FK Controller` 通过局部 X 位移驱动 IK 权重；没有现成动画或 Shape Keys。附件说明不构成实施指令。原始文件和许可证保存在 `Assets/Art/Horse/Source/`。导出脚本在 Blender 2.83 的 factory startup 模式下应用镜像、去掉非变形控制骨骼及 Blender 约束，再导出 FBX。

八项可编辑属性：胖瘦、前腿长、后腿长、身长的倍率均为 0.85～1.15；前后腿力量倍率均为 0.55～1.45；体重 250～750 kg；蹄子光滑度 0～1。随机生成使用体架、脂肪、前后肌肉倾向与固定 seed。体宽为 `clamp(1+0.05×体架+0.10×脂肪)`，身长含体架及独立扰动，前后腿长差不超过 0.20；体重按 `450×体宽²×身长×(0.8+0.2×平均腿长)×密度扰动` 推导；力量由体架和对应肌肉倾向推导。随机结果和手动覆盖使用同一个 `HorseConfig`。

每马拥有独立网格和蹄子物理材质。导出 FBX 包含胖／瘦、前后腿长／短、身长／短共八个主要 Shape Keys，另有前后腿肌肉修形。运行时胖瘦使用 Shape Key，腿长通过腿骨段位置，身长通过显示根尺度，肌肉通过每马独立网格局部修形；物理骨架在配置应用时重建。运行中仅编辑待应用配置，点击重置后才替换刚体尺寸。后续在 Unity 实测时应优先检查所有倍率边界的蒙皮与碰撞对应关系。

## 物理与控制契约

每匹马 19 个刚体：躯干、颈、头、四腿各四段。躯干占体重 60%，颈 8%，头 4%，每腿 7%。12 个主动关节拥有 16 个角度自由度；蹄、颈、头使用被动弹簧关节。Unity 固定物理步为 0.01 秒，控制器每 0.05 秒输出一次动作。

`HorseAction v1` 为 28 维连续值。前 16 维依次是左前、右前、左后、右后四腿的腿根前后、腿根侧向、中间屈伸和下段屈伸；后 12 维为每腿三个主动关节的驱动强度。所有值范围为 [-1,1]，非法值拒绝应用。`HorseObservation v1` 的组件顺序由 `HorseActor.BuildObservation` 定义，标准四马时应为 254 维，包含躯干速度和方向、18 个关节的姿态及角速度、四蹄状态、马自身属性、赛道状态、三匹对手状态和上次动作。显示系统不参与观测。未来 ML-Agents 仅负责将这些数据转换到训练器。

跨马身体、头颈、腿部碰撞开启；同马躯干与腿和直接相连骨段的碰撞忽略。蹄子光滑度通过每马独立 PhysicsMaterial 映射到摩擦，赛道地面摩擦为 1。状态机为 `Standing → Unstable → Fallen → Recovering → Standing`。躯干倾斜超过 65° 达 0.35 秒或地面接触达 0.2 秒视为倒地；辅助扶起不得增加纵向进度，附近空间不足则继续等待。恢复操作产生独立事件。

## 画面和交互

URP 卡通材质使用柔和分段明暗、暖主光及冷环境光。四匹马分别使用毛色区分。碰撞、打滑和倒地从真实物理事件触发尘土、声音和星形冲击；特效使用对象池。属性面板、seed、单马／全部随机、配置保存／读取、暂停、重置、镜头切换及三档四方向推力测试均在运行时建立。

## 验收顺序

1. Unity Editor 能导入工程；运行 `QHOP → Generate presentation scenes`；两个场景各出现四匹马，FBX 骨骼和材质完整。
2. 静止标准体型在平地持续站立 20 秒。验证四腿支撑确实来自关节驱动，躯干没有隐藏冻结或悬浮力。
3. 检查四项外观属性的最小／默认／最大组合，共 81 组。核对网格、骨骼、碰撞体、地面接触和相机包围盒。
4. 生成 1000 组属性，检查边界、相同 seed 重现和可解释的体型／数值关联。
5. 进行侧撞、迎面撞、撞倒地马、四马拥挤、快速蹄部接触；核查无持续穿透或非数值刚体状态。
6. 在夹具上比对低／高蹄子光滑度的平均滑动，检查反复摔倒和辅助扶起的纵向位置。
7. 连续重置 100 次；记录残留速度、碰撞、粒子和材质共享问题。核对动作 28 维、观测 254 维与非法动作处理。
8. 在实际测试机器上记录 1080p 四马帧时间、物理耗时和内存；60 FPS 是目标，不应在未实测前宣称达标。
9. Windows x64 构建打开两个场景，检查中文字体、声音、按钮和相机；再由录像确认四马的外观差异与摔倒趣味性。
