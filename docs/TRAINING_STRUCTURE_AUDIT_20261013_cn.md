## 2. 物理骨架及可驱动骨骼

实际是 19 刚体、18 个 ConfigurableJoint：躯干 1，颈和头 2，四腿各 4。12 个腿关节受策略主动控制，4 个蹄关节及颈/头两个关节为被动弹簧。

躯干把 Base、Pelvis、Chest 合并到一个 Rigidbody，没有脊柱、骨盆或胸部独立动作。脖子和头有独立物理运动，但没有策略输出。脚趾没有独立刚体，跟随该腿蹄刚体。其他可见骨骼按绑定映射跟随物理身体，不能按模型骨骼总数推断控制自由度。

| 左前 FL | ForeThigh.L：0 / 1 | ForeThigh.L.001：2 | ForeCalf.L：3 | 16 / 17 / 18 | ForeFoot.L / ForeToe.L |
| 右前 FR | ForeThigh.R：4 / 5 | ForeThigh.R.001：6 | ForeCalf.R：7 | 19 / 20 / 21 | ForeFoot.R / ForeToe.R |

## 3. 驱动方式和物理参数

### 3.1 动作到驱动器

所有动作范围 [-1,1]。主角度非对称映射：正动作乘 Max，负动作乘 -Min，例如前腿中段 +1→屈曲 75°，-1→反向 8°，0→静息。

腿根侧摆角 = 侧摆动作 × 12°。描述器把前后目标、侧摆目标及静息旋转组合，再转换为 Joint.targetRotation。

驱动为 ConfigurableJoint 的 Slerp 位置弹簧/阻尼，概念上相当于带最大力矩限制的 PD 伺服，不是直接输出瞬时力矩，也不是直接播放动画或设置每帧骨骼旋转。

强度动作 a 的转换：`power=(a+1)/2`；`maximumForce=40000 × 前/后腿力量系数 × power`。a=-1 时主动驱动上限为零，a=0 为一半，a=+1 为满额。它只调整 maximumForce，不调整弹簧刚度和阻尼。

| 项目 | 主动腿关节 | 被动颈/头/蹄 |
|---|---:|---:|
| positionSpring | 60,000 | 5,000 |
| positionDamper | 3,000 | 350 |
| maximumForce | 0～40,000 × 力量系数 | 5,000 |

rootDrive 虽然名为 root，实际用于全部 12 个主动关节。所有主动关节共用同样的基础弹簧、阻尼和上限，没有按根部/中段/下段的惯量分别缩放。髋/肩摆动与膝/下段屈伸的符号和正负范围不同，但基准驱动参数相同。

关节三个平移方向锁定，三个旋转方向有限位，采用 PositionAndRotation projection。相邻刚体及躯干与本马其他碰撞体之间忽略碰撞；其余非相邻肢体仍可能碰撞。

### 3.3 摔倒和程序恢复

躯干倾斜超过 65°，或高度低于静息高度 55%，或躯干触地，会进入 Unstable。持续失稳 0.35 秒或持续触地 0.2 秒判 Fallen。

Standing 和 Unstable 可接受策略动作；Fallen/Recovering 不接受。Fallen 时 12 个主动关节的 maximumForce 被设为零，被动关节仍有弹簧。ApplyAction 内虽有 Fallen 时 power×0.25 的分支，正常外部策略入口先拒绝 Fallen，所以不能理解为策略还能以四分之一力量自行爬起。

摔倒通常不会立即终止回合。等待至少 3 秒，程序寻找允许恢复且没有障碍的区域，把全部刚体速度清零、移到摔倒判定位置对应的静息姿态，恢复默认角度 0 / 强度 0.7。下一物理帧恢复动态。恢复位置以进入 Fallen 时的位置为基准，不奖励复位位移。

这是辅助复位，不是学到的自主起身。当前训练与预览均启用 allowRecovery；preview 的 training=false 主要影响可见骨骼跟随/描边。

## 4. 全部奖励结构

每 0.01 秒物理帧计算并 AddReward，策略每 0.05 秒收到累计奖励。定义：

- p=本帧有效前进距离 / 静息躯干高度；历史最远位置 highWater 限制往复刷距离。
- u=clamp(dot(躯干上方向,世界上方向),0,1) × clamp(当前高度/静息高度,0,1)。
- b=clamp((1-u)+abs(世界横向速度)/10+abs(世界 Y 角速度)/10,0,1)。其角速度项惩罚偏航，未独立直接惩罚 X/Z 翻滚角速度。
- s=clamp(sum((当前动作-上一物理帧动作)^2)/(28×4),0,1)。动作通常每五帧改变一次；该项按物理帧差分计算，不是把同一动作变化持续惩罚五帧。
- e=12 个 `power²` 的均值；这是控制强度代理量，不是实际机械功或关节力矩做功。
- l=触地蹄水平速度/5 的截断值，四蹄平均；是世界水平滑动代理量。
- n=本帧新增摔倒次数；q=正确周期/全部周期；rank=(参赛马数-名次)/(参赛马数-1)，单马为 0。

有效前进要求策略活跃、躯干未睡眠、up 点积>0.55、高度>65% 静息高度、躯干未触地、横向位置在 ±6 米内。完全倒地滚动距离会被过滤；失稳前后暂时满足姿态门槛的移动仍可计分。到达终点还检查正向速度及同类姿态条件，但不要求无摔倒、正确步态或四腿参与。

### 4.2 步态奖励和识别

所有阶段都有步态项，权重 w：Stage 1=0.1，Stage 2=1，Stage 3～7=0.25。

| 项 | 基础权重（再乘 w） | 条件/含义 |
|---|---:|---|
| 四腿参与 | +0.10 每秒 | 最近窗口有效落蹄腿数/4 |
| 连续协调 | +0.90 每秒 | C=(0.75支撑匹配+0.25四腿参与)×正确前缀 |
| 顺序过程 | +0.20 的时间额度 | 正确落蹄组/前缀消费累积额度，不能按事件数量无限刷 |
| 正确周期 | +0.75×周期覆盖秒数 | 周期结束结算，未完成周期不发正确奖 |
| 乱序/错误周期 | -0.75×覆盖秒数 | 无合法候选等 |
| 非法同步 | -1.50×覆盖秒数 | 同侧或同前/后非法同步，合法对角配对另处理 |
| 缺腿 | -0.50×覆盖秒数 | 缺失/超时周期 |
| 拖蹄 | -0.30×覆盖秒数 | 无效落蹄事件 |
| 高抬蹄 | -0.60×High² 每秒 | 腿长归一化，扣除身体上升，修正地面 |
| 折叠/超软阈值 | -0.60×Fold² 每秒 | 16 个腿关节（含被动蹄）中的最大 SoftError |

正向项另要求有效前进、vz>0.2。负向周期标签可重叠。同物理帧全部落蹄组完成验证后才给过程奖励；摔倒、结束时结清未完成负项。

接触信号连续两个物理帧变化才确认。有效一次落蹄要求：前次支撑与本次摆动各至少约 0.029 秒，净抬蹄至少腿长 2%，向前摆动至少腿长 5%。同步容差=周期的 8%，限制在 0.02～0.06 秒。不是固定动画时钟。

- 走步：HL→FL→HR→FR 四拍，周期 0.6～2.5 秒，可循环移位。
- 小跑：FL+HR ↔ FR+HL 对角两拍，周期 0.35～1.5 秒。
- 三拍跑：HR→(HL+FR)→FL 或 HL→(HR+FL)→FR。
- 疾驰：HR→HL→FR→FL 或 HL→HR→FL→FR 四拍。
- Stage 1 允许走步/小跑；Stage 2 按子任务限制小跑/三拍/疾驰；Stage 3～7 允许上述合法步态切换。

High 的抬蹄容许值：通常腿长 25%，三拍 35%，疾驰 40%；再高出腿长 20% 时 High=1。Fold 对主方向角的软范围误差归一化至硬限位，取最大值；没有对每个关节误差求和，也没有用目标角代替实际角。

### 4.3 “零 shaping”的实际边界

Stage 7 h=0 时，距离、姿态、动作变化、努力、滑移、摔倒的基础 shaping 归零；时间、终局奖励仍存在。步态 w 仍是 0.25，包括参与/协调/过程/周期及乱序/同步/缺腿/拖蹄/抬蹄/折叠，因此不是所有过程奖励归零。

### 5.2 Actor/Critic 编码器

Actor 和 Critic 各自拥有完整、独立参数的同结构 Encoder，不共享编码器权重。

```text
70 地形 ───── Linear/ELU 64 ── Linear/ELU 64 ────────────┤
3×11 对手 ─── 共享 Linear/ELU 32 ─ Linear/ELU 32         │
              按有效标记池化 mean32 + max32 ─────────────┤
                                                        ↓
                                                 concat 384
                                                 256 ELU
                                                 128 ELU
28 步态 ───── Linear(28,128,bias=False，零初始化) ────── 加和
                                                        ↓
                                  Actor: Linear128→28 / Critic: Linear128→1
```

实际参数数目：Actor 463,704，Critic 460,193，总计 923,897。不含归一化统计与 Adam 状态。

没有 LSTM/GRU、Transformer、卷积、显式步态振荡器、参考动作模仿损失、左右对称参数约束，也没有关节级子策略。四腿协同主要靠奖励和观察学习。

### 5.3 动作分布与初始化

Actor 输出 28 维高斯均值。训练在各维独立 Normal 中采样 raw，再 tanh 到 [-1,1]，log probability 包含 tanh Jacobian 修正；评估/预览直接 tanh(mean)。

log_std 为 28 个可训练但不依赖状态的参数，截断 [-4,0.5]。角度初值 -1.4（raw 标准差约 0.247），强度初值 -1.8（约 0.165）。角度均值输出层零 bias，小增益正交权重；强度 bias=atanh(0.7)，故初始强度动作接近 0.7，也就是 85% 驱动上限、标准马约 34,000。

初始角度噪声并不微小：前腿下段 raw 一个标准差经 tanh 后约 +24.2°或 -1.94°；中段约 +18.1°或 -1.94°。这是映射示例，不是实际初始角度分布统计。因正负范围不对称，零中心随机动作也不保证角度目标均值为零。12 个角度/4 个侧摆各自独立采样，初始化没有四腿相位关系。

动作每 0.05 秒更新并保持；没有目标角变化率限制或动作低通滤波。零动作姿态仍需承重，静息目标本身并不提供平衡控制器。

## 6. PPO 与课程

自定义 PyTorch PPO，经 ML-Agents 通信与 Unity 相连，不是单纯套用官方 trainer YAML。

| 项 | 当前默认 |
|---|---|
| 每次采样 | 16,384 马匹决策样本 |
| minibatch / epochs | 1,024 / 最多 5 |
| gamma / GAE lambda | 0.999 / 0.95 |
| policy clip / value clip | ±0.2 / ±0.2 |
| value loss 系数 | 0.5 |
| KL 提前结束更新 | approx_kl>0.02 |
| 梯度范数截断 | 0.5 |
| optimizer | Adam，betas=(0.9,0.999)，eps=1e-5 |
| 学习率 | 每阶段重置 warmup + cosine，末端为 peak 的 10% |

前两阶段每 25 次更新评估，后续每 100 次。只在 actor_mask 有效样本上计算策略/熵损失并归一化策略 advantage；Critic 仍训练全部样本。GAE 沿同马 stream 回传，Fallen 不等于 done，因此等待和后续损失不是完全不能影响之前动作。

gamma=0.999 对 20 Hz 决策约有 50 秒折扣尺度，但 gamma×lambda≈0.949 的 GAE 衰减尺度约 1 秒；不能仅用 gamma 断言摔倒后 3 秒后果的信用分配充分。

| 阶段 | 内容 | 预算 | peak LR | entropy |
|---|---|---:|---:|---:|
| 1 | 标准马平地前进；2/5/10/20 米 | 300 万 | 3e-4 | 0.01 |
| 2 | 小跑/三拍/疾驰；30/50/80 米，固定 20 秒 | 800 万 | 1.5e-4 | 0.01 |
| 3 | 稳定高效，100 米/45 秒 | 800 万 | 3e-4 | 0.005 |
| 4 | 体型泛化，100 米/45 秒 | 1200 万 | 3e-4 | 0.005 |
| 5 | 路况/摩擦/扰动恢复，100 米/60 秒 | 1500 万 | 3e-4 | 0.005 |
| 6 | 四马真实碰撞，100 米/90 秒 | 1500 万 | 1.5e-4 | 0.003 |
| 7 | 完整随机比赛与基础 shaping 退火 | 1000 万 | 1e-4 | 0.001 |

前五阶段各 worker 8 区域、每区域一马；后两阶段 2 区域、每区域四马，含当前及冻结历史策略对手机制。单马阶段没有对手特征的实际比赛信号。

Stage 1 子任务：2 米/10 秒→5 米/15 秒→10 米/20 秒→20 米/20 秒。前三级晋级要求评估完成率≥80%、无摔倒完成率≥60%；最终需完成率≥90%、无摔倒完成率≥80%，连续三次。此次仍在第二子任务，300 万步没有触发自动进入自然步态训练。

Stage 2 暖身速度 1.5～2 m/s，随后小跑 2～4、三拍 4～6、疾驰 6～9。需要覆盖≥90%，完成率≥90%，无摔倒≥85%（最后90%），速度带≥80%，正确周期≥80%（最后85%），最后还要求同步周期和高抬蹄各≤5%。第三至第七阶段继续保留步态验收条件。

## 7. 为什么当前可以得到“翻滚但奖励为正”

### 7.1 已确认：优化目标和用户期望存在差距

最近训练 100 回合的平均奖励分解：

| 分项 | 回合均值 |
|---|---:|
| 前进 | +6.20569 |
| 完赛 | +1.84000 |
| 步态正项 | +0.01932 |
| 姿态 | -0.66713 |
| 时间 | -0.57523 |
| 摔倒 | -0.52500 |
| DNF | -0.08000 |
| 错误步态 | -0.95794 |
| 抬蹄 | -0.07737 |
| 折叠 | -0.53443 |
| 合计 | +4.64790 |

这不是“无步态奖励”：它有，但第一阶段乘 0.1，主奖励来自推进和完赛。正确周期为零仍能获得正总回报。策略可以通过短暂满足姿态门槛的失稳推进、摔倒、程序复位、继续推进获得回报；日志与用户描述相符，但没有逐帧轨迹，不能证明具体翻滚旋转轴或完整策略序列。

训练目标不能只看 reward_total。完成率也不等于站稳完成：终点没有无摔倒约束；课程晋级的无摔倒门槛只决定是否进入下一任务，不自动增强 Actor 的当前奖励。

Stage 1 没有动作变化、努力和滑移基础惩罚；姿态项封顶只有约 -0.1/秒；每次摔倒 -0.25。这些使不协调、高幅度目标及反复失稳相对便宜。程序复位承担了起身难题；Agent 只需要学到复位之间的推进。

### 7.2 已有独立证据：站立物理基础没有通过稳定性验收

工作区 `training/gait-r13-validation.md` 记载：不进行前置通道扰动的冷启动站立检查，104 回合累计 32 次摔倒，最低归一化躯干高度约 0.267。它是既往运行证据，本次仅核对记录，未重跑；不能视为当前新测结果。

该失败发生在零角度/站立控制下，说明此前版本连静息承重都不稳定。96 组单关节限位/到达测试通过，以及一秒承重通过，只能验证各自范围，不能证明长期多关节承重/行走稳定。

因此至少有两条应分别验证的机制：物理承重基础失败；奖励让失稳推进仍有利。当前证据不能确定具体物理根因，更不能据此直接指定某个弹簧参数必错。

### 7.3 待验证的结构风险

1. 高刚度伺服、各段同参数、躯干/远端质量差距、足底接触和关节投影之间可能存在振荡/求解耦合。需观察目标/实测角、接触和刚体能量，不能凭参数数值判断。
2. 独立探索叠加不对称角度映射，从启动就可能同时折叠多条腿；没有先获得支撑再增加步态探索的过程。
3. 0.15 秒历史短于完整周期，虽有事件记忆输入，仍缺少显式控制相位。网络是否不足要在物理/奖励可解后验证。
4. 最后 batch 仅45.69%对 Actor 有效，意味着300万总样本不是300万主动控制样本。末期大量样本用于等待/恢复降低了有效探索效率。
5. 原预算只对应184次PPO更新，已到3e-5；继续原调度不能自然恢复初期探索/学习速度。是否应重置调度应作为独立实验变量。
6. 训练采样和确定性评估差距大；应比较同种子同初态，而不是根据92%完成率认为策略已经掌握稳定行走。

## 8. 建议的下一轮分析顺序

1. **静息承重基线**：固定体型与地面，确定性零角度/强度0.7，长于完整任务窗口；记录首次失稳时刻、躯干姿态/速度、各腿实测/目标角、碰撞接触及关节上限。先复现站立失败。
2. **逐关节与单腿承重**：区分肩/髋、前后中段和下段；检查碰撞体是否真正支撑、静息几何、限位方向、质量/惯量及驱动力饱和。单关节到达测试不能替代此步骤。
3. **翻滚逐帧回放**：用同 checkpoint、同种子分别确定性和随机采样，记录有效前进门槛、失稳/Fallen切换、每项奖励和程序复位时刻，确认每次拿分的动作段。
4. **奖励对照**：在相同物理基础上比较稳定前进、失稳推进和原地站立的完整回报。决定是否拆成站稳→单腿摆动→多腿协调，而不直接以大幅奖励改动掩盖物理问题。
5. **控制/网络实验**：基础修复后再分别考察探索幅度、目标变化率、关节独立参数、周期状态/更长历史或循环网络；每次改变一种机制。

这些是分析建议，本次没有修改限位、驱动、奖励或启动额外训练。
