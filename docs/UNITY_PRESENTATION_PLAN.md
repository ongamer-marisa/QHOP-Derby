# Unity 4頭立てレース展示の実装・受け入れ計画

[简体中文](UNITY_PRESENTATION_PLAN_cn.md) · [プロジェクト概要](../README.md)

## 確定した製品範囲

対象ディレクトリは `D:\dev\QHOP Derby` です。初版は各4頭の2シーンを納品します。`AttributeLab` は属性と衝突の実験、`DerbyStraight` は100 m直線レースの展示に使います。馬は物理関節で体重を支え、衝突します。初版のコントローラーは起立のみを試み、PPO による自律走行は後の段階です。既定カメラは斜め上からの側面視点で、単独馬視点と自由視点に切り替えられます。転倒して約3秒後に補助して起こしますが、学習時には補助を無効にします。

## モデルと設定

付属の `Horse.blend` には51本のボーン、40本の変形ボーン、964個の三角面、4つのマテリアルスロットがあります。4本の脚には3ボーンの IK チェーンがあり、`IK-FK Controller` はローカル X 移動で IK ウェイトを駆動します。既成のアニメーションや Shape Keys はありません。添付の説明は実装指示ではありません。原本とライセンスは `Assets/Art/Horse/Source/` に保存しています。エクスポートスクリプトは Blender 2.83 の factory startup モードでミラーを適用し、変形に使わない制御ボーンと Blender の制約を除いて FBX を出力します。

編集可能な8属性は次のとおりです。肥満度、前脚長、後脚長、胴長の倍率は各0.85～1.15、前脚力と後脚力の倍率は各0.55～1.45、体重は250～750 kg、蹄の滑らかさは0～1です。ランダム生成には体格、脂肪、前後の筋肉傾向、固定 seed を使います。体幅は `clamp(1+0.05×体格+0.10×脂肪)`、胴長には体格と独立した揺らぎを反映し、前後脚長の差は0.20以下にします。体重は `450×体幅²×胴長×(0.8+0.2×平均脚長)×密度の揺らぎ` から導きます。力は体格と対応する筋肉傾向から導きます。ランダム生成と手動上書きは同じ `HorseConfig` を使います。

馬ごとに独立したメッシュと蹄用 PhysicsMaterial を持ちます。FBX には肥満／痩身、前脚の長／短、後脚の長／短、胴の長／短の8つの主要 Shape Keys と、前後脚筋肉の変形が含まれます。実行時、肥満度は Shape Key、脚長は脚の骨区間の位置、胴長は表示ルートのスケール、筋肉は馬ごとのメッシュの局所変形で表します。物理骨格は設定を適用するときに再構築します。実行中の編集は適用待ちの設定に限り、リセット後に剛体寸法を差し替えます。Unity での実測では、各倍率の境界値でスキンと衝突体が一致するかを優先して確認します。

## 物理と制御の契約

馬1頭は19剛体です。胴、首、頭、4本の脚に各4区間があります。体重の配分は胴60%、首8%、頭4%、各脚7%です。12個の能動関節に16個の角度自由度があり、蹄、首、頭には受動ばね関節を使います。Unity の固定物理ステップは0.01秒、コントローラーのアクション出力は0.05秒ごとです。

`HorseAction v1` は28個の連続値です。最初の16個は左前、右前、左後、右後の順で、各脚の付け根の前後・左右、中間部の屈伸、下部の屈伸を表します。残り12個は各脚の3能動関節の駆動強度です。範囲はすべて [-1,1] で、不正な値は適用を拒否します。`HorseObservation v1` の構成順は `HorseActor.BuildObservation` で定義し、標準的な4頭立てでは254次元を想定します。胴の速度・方向、18関節の姿勢と角速度、4蹄の状態、馬自身の属性、コース状態、3頭の対戦相手、直前のアクションを含みます。表示システムは観測に関与しません。将来 ML-Agents はこのデータを学習器へ渡す役割のみを担います。

別の馬同士では体、頭・首、脚の衝突を有効にします。同じ馬の胴と脚、および直結する骨区間の衝突は無視します。蹄の滑らかさは馬ごとの PhysicsMaterial の摩擦に対応し、コース地面の摩擦は1です。状態遷移は `Standing → Unstable → Fallen → Recovering → Standing` です。胴の傾きが65°超で0.35秒続くか、地面との接触が0.2秒続くと転倒と判定します。補助して起こす際に進行方向の距離を増やしてはならず、周囲の空間が不足すれば待機します。復帰は独立したイベントを発生させます。

## 画面と操作

URP のトゥーン材質は柔らかな段階的陰影、暖色の主光源、寒色の環境光を用います。4頭は毛色で区別します。衝突、滑走、転倒の実際の物理イベントから砂煙、音、星形の衝撃演出を発生させ、エフェクトにはオブジェクトプールを使います。属性パネル、seed、単独馬／全馬のランダム生成、設定の保存／読込、一時停止、リセット、カメラ切り替え、3段階・4方向の力の試験は実行時に構築します。

## 受け入れ順序

1. Unity Editor にプロジェクトをインポートし、`QHOP → Generate presentation scenes` を実行します。2シーンに各4頭が現れ、FBX のボーンとマテリアルがそろっていることを確認します。
2. 標準体形の馬が平地で20秒間起立し続けることを確認します。4脚の支持が関節駆動によるもので、胴を隠れて固定したり浮力を加えたりしていないことを調べます。
3. 外観4属性の最小／既定／最大の組み合わせ81組を調べ、メッシュ、ボーン、衝突体、接地、カメラの外接範囲を照合します。
4. 属性を1000組生成し、境界値、同じ seed による再現、体形と数値の説明可能な関係を確認します。
5. 横・正面からの衝突、転倒した馬との衝突、4頭の密集、速い蹄の接触を試し、持続的な貫通や不正な剛体数値がないかを確認します。
6. 試験装置で蹄の滑らかさが低い場合と高い場合の平均滑走を比較し、反復転倒と補助復帰で進行方向の位置が不当に変わらないかを確認します。
7. 100回連続でリセットし、残留速度、衝突、粒子、マテリアル共有の問題を記録します。28次元アクション、254次元観測、不正なアクションの処理も確認します。
8. 実際の試験機で1080p・4頭のフレーム時間、物理処理時間、メモリを記録します。60 FPS は目標であり、実測前に達成を主張しません。
9. Windows x64 ビルドで2シーンを開き、中国語フォント、音、ボタン、カメラを確認します。さらに録画で4頭の外観差と転倒演出の面白さを確認します。

## 検証記録

- Blender 2.83 の factory startup で FBX を出力して再インポート済みです。出力ボーン40本、三角面964個、マテリアルスロット4個で、主要な体形変形8端点と筋肉変形2種が存在し、頂点が変化することを確認しました。
- Unity ソースはローカルの Unity 6 に付属するアセンブリと Roslyn コンパイラーで静的コンパイルし、C# エラーはありませんでした。
- 当初の Unity コマンドライン起動では `No valid Unity Editor license found` と報告され、当時はインポート、シーン実行、物理調整、視覚受け入れ、Windows ビルドを行えませんでした。その後の実施結果は[新しい検証記録](VALIDATION.md)を参照してください。
- Editor ライセンスが使える環境では、上記の順序で受け入れ検証を進め、関節制限、駆動、視点を調整します。静的コンパイルだけでは関節の動作安定性や描画の正しさを証明できません。
